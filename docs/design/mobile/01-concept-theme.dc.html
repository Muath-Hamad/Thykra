Editions,
in hand.

Wanderlust Editions already exists. The web app shipped it, the tokens are frozen in tokens.css, and the server grew the endpoints the mobile app was missing. This is not a second design system; it is the same one, re-set for a 393 dp column that is held in one hand and read at arm's length.

Two things genuinely change on the phone. The thumb replaces the cursor, so primary actions move to the bottom edge and the top bar goes quiet. And the phone is where the photographs are, so contribution — picking, uploading, watching it finish — becomes a first-class journey with its own component, not a chip in a corner.

This part stops after the theme. Every value below is transcribable into ColorScheme, Typography and Shapes, plus one small ExtendedColors class for what Material has no slot for. Screens follow once you have signed this off.

Concept note

What stays identical, so the two read as one product

A screenshot of a trip on web and on a Pixel should be recognisably the same page at two widths. That holds if these eight things are not touched:

Token names and values

Every hex in this document is copied from tokens.css. Where Material needs a colour the web never defined, it is derived and marked derived so it can be added to both token files.

Paper and Darkroom

Same bone, same near-black, same rule that the viewer is always dark. system | paper | darkroom persists in DataStore under the same three names the web stores in localStorage.

Two accents, split by meaning

Blue is what the system does; clay is what people do. Stricter than the web's first draft: Add photos is blue. Only Join, Invite friends, avatars and the Stamp are clay.

The plate

Media at 0 dp radius and true aspect from width/height, with a 1 dp hairline outline. Chrome soft, content square — identical contrast on both platforms.

Day chapters

Same grouping code path (port chapters.ts to shared/), same numeral, same 2 dp rule, same lead plate, same "Added later" bucket for undated media.

The Stamp

Double-ruled, clay, −3° in LTR and +3° in RTL, on invite and share surfaces only. Never more than one on screen.

Type families

Archivo Expanded for display, Readex Pro for everything else and for all Arabic, bundled — no more system sans with a weight map.

Voice

"Trip", never "Album". Second person, present tense. One italic clay phrase per headline in English; weight instead of italic in Arabic. Two celebrations in the whole app: first upload finishing, and joining.

What changes at 393 dp

One column, always

Web mastheads put the title beside the cover. On the phone everything stacks: cover plate first (16:9, edge to edge, no gutter), then the title at displayLarge 44 sp, then people and counts on one line. Trip cards are one per row at 393 dp and two per row from 600 dp (medium window class). Nothing is ever three-up on a phone.

Justified rows become a staggered grid

A justified row needs 3–5 items to look right; at 393 dp it gets 2 and looks like a broken table. So each chapter is a LazyVerticalStaggeredGrid with 2 columns portrait, 3 landscape, 4 on tablets, 3 dp gaps, each plate at its own aspect. The lead plate spans both columns and is capped at 56% of the window height (not 62% as on web — the bottom bar and status bar eat the difference). The contact sheet is a uniform 3-column square grid, 2 dp gaps.

Quiet top, busy bottom

The 56 dp top bar carries a back affordance, a title that only appears once the masthead has scrolled away, and at most two icon actions. Primary actions live in the bottom 30% of the screen: the four-tab NavigationBar on root screens; on the trip screen, an action bar pinned above the nav inset with Add photos (filled blue), Share (tonal) and the upload dock riding above it. Destructive actions are never in the thumb zone — they sit at the end of a settings scroll or behind a sheet.

Sheets replace dialogs, dialogs remain for one thing

Create trip, share, member actions, comments, reaction picker, the upload target picker — all ModalBottomSheet, rising from the thumb's edge. The only AlertDialog left in the app is the destructive confirm, because a decision that cannot be undone should not be dismissable by an accidental swipe.

The dashed arc is a comfortable right-thumb sweep. Everything a user does more than once a session — add photos, react, open a sheet, switch tabs — falls inside it. Everything they do once — sign out, delete, revoke — is deliberately outside it. Left-handed and RTL users get the mirror; nothing depends on a corner.

360 dp is the floor, not an afterthought

Below 380 dp of width, display styles step down one slot (displayLarge → displayMedium, and so on) via a compactTypography instance chosen at the theme root. Gutters stay 16 dp. Nothing hides; the type simply gets one size smaller so a trip title still fits on two lines.

Theme resolution

isSystemInDarkTheme() unless the DataStore preference says otherwise. Applied at the ThykraTheme root before the first frame — read the preference synchronously from the cached DataStore value, never as a suspended default, or the app flashes Paper for one frame on a Darkroom phone.

Always Darkroom

The media viewer wraps itself in ThykraTheme(dark = true) regardless of the preference, and asks for light status-bar icons via the insets controller for its lifetime. It is the one place the two themes converge.

Never Darkroom

The landing screen keeps its photograph wall and fixed art direction in Paper only, matching the web's /. It is a first impression, not a working surface.

Three decisions to sign off before screens

1 · Bottom bar hides on nested screens

The four tabs show only on trips, activity, recaps, me. Inside a trip, the bar gives its 60 dp to the trip's own action bar (Add photos · Share · ⋯), and the upload dock rides above that. This is how the phone gets a permanent, thumb-reachable Add photos without a FAB floating over plates. Back returns to the tab root with the bar restored.

2 · Button labels are Readex, not Archivo

The web set button labels in Archivo 600. Archivo Expanded at 15 sp inside a 48 dp button eats 25% more width, and at 360 dp two side-by-side buttons stop fitting. So labelLarge — buttons, segmented, tabs — is Readex Pro 600. Display stays Archivo Expanded everywhere it is display. This is the single intentional type divergence; the web may want to follow.

3 · text-3 is not outline

Brief §4.2 maps both --text-3 and --rule-strong to outline. In Material, outline draws borders — OutlinedButton, OutlinedTextField, dividers — and a 20% hairline is right for those while #5C6B7A is far too heavy. So outline = rule-strong, and --text-3 becomes the extended colour textMeta. No component loses a colour; one gains a name.

Font files — 590 KB
  • archivo_expanded_semibold.ttf and archivo_expanded_bold.ttf — two static instances cut from the Archivo variable font at wdth=125, Latin only, ≈ 70 KB each.
  • readex_pro_variable.ttf — one variable file, Latin + Arabic, ≈ 450 KB. Weights 400 / 500 / 600 selected with FontVariation.weight() — supported on API 26+ and on iOS through Skia, so it is safe in commonMain.

Arabic typography instance

A second Typography value, arabicTypography, chosen at the theme root when the app locale is ar. Every display and headline slot switches to Readex Pro 700 (600 for headlines) at 0.92× size and 1.32× line height; tracking is 0 everywhere; labelSmall loses its tracking and is never uppercased. The italic clay phrase becomes weight 700 in the same colour. numeral stays 40 sp but renders Arabic-Indic digits via NumberFormat for locale ar; every other number in the app is Western.

Dynamic type to 200%

All sizes are sp, so they scale. Two guards: display slots and numeral read fontScale.coerceAtMost(1.5) — a 44 sp title at 200% is 88 sp and no longer a title — while body and label scale fully. Layouts that hold display text never fix their height. The chapter header and the pinned bar are the two places this is tested at 200% before anything ships.

enum class ThemeMode { System, Paper, Darkroom }

@Composable fun ThykraTheme(
  mode: ThemeMode = LocalThemeMode.current,
  forceDark: Boolean = false,            // the viewer passes true
  content: @Composable () -> Unit,
) {
  val dark = forceDark || when (mode) {
    ThemeMode.System -> isSystemInDarkTheme()
    ThemeMode.Paper -> false
    ThemeMode.Darkroom -> true
  }
  val compact = LocalWindowInfo.current.containerSize.width < 380.dp
  val arabic = LocalLocale.current.language == "ar"
  CompositionLocalProvider(
    LocalExtendedColors provides if (dark) darkroomExtended else paperExtended,
    LocalMotion provides motion,
    LocalReducedMotion provides platformReducedMotion(),
    LocalElevation provides if (dark) darkroomElevation else paperElevation,
  ) {
    MaterialTheme(
      colorScheme = if (dark) darkroomScheme else paperScheme,
      typography = typographyFor(arabic, compact),
      shapes = thykraShapes,
      content = content,
    )
  }
}
val MaterialTheme.thykra: ExtendedColors
  @Composable get() = LocalExtendedColors.current

Three values to add to tokens.css

So web and mobile stay one file apart, not two: --bad-text (#A32D26 / #F5A39C), --good-text (#146041 / #8FD9B3), --warn-text (#6B4708 / #EDC680). The web currently has none of the three and is using --bad as text on --bad-soft, which is 4.4:1 in Paper — just under AA. Small win for both platforms.

iOS check

Nothing above is Android-only. Modifier.shadow with tinted colours, variable-font axes, LayoutDirection.Rtl, ModalBottomSheet and NavigationBar all render through Skia on iOS. The only expect/actual pairs the theme needs are platformReducedMotion() and the status-bar icon colour request the viewer makes.
